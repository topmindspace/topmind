# topmind 三仓架构与智能体审查

审查日期：2026-10-24。范围：`topmind-skills`、主仓库 Kernel / Desktop / Clip、`topmind-obsidian`。本报告区分代码与本地测试确认的问题、设计判断及尚待真实使用验证的目标。没有调用付费模型做线上效果评测，也不把静态检查通过等同于产品体验已验证。

## 结论

**产品基础合理，规约和编排层已经过重。优先减少重复决策、重复上下文和重复确认，再增加能力。** 本地 Markdown、文件可直接编辑、统一契约、共享写闸和按需加载技能应保留。问题不在“10 个技能一定太多”，而在入口、技能、shared、system prompt、工具描述和完成判定重复解释同一件事，且解释已互相冲突。

不建议全面重写、把三个仓库强行合并、立即引入向量数据库或多智能体调度平台。先改善一个用户请求从自然语言到可验证结果的闭环。

## 保留、精简、优化、加强

| 项目 | 判断与证据 | 处理方向 |
|---|---|---|
| Markdown 为内容真源 | 可离开 Desktop 使用；Kernel 与 Vault UI 分离 | 保留。避免再造会话中的第二份内容数据库 |
| topmind.yaml / 三平面 | 路径、角色、保护与系统状态有真实差异 | 保留兼容；面向用户隐藏“平面、卫星、八引擎”等实现术语 |
| 写闸与路径围栏 | 数据保护、原子写、锁定首写快照、确认队列由代码实施 | 加强执行测试；不能因模型能力增强而移除 |
| 6 条内容约定 | 部分是组织建议，部分是兼容约束；“大类不重叠”无法确定性证明 | 默认建议，不做自动整理理由；用户的结构和明确要求优先 |
| 单一日常入口 | 用户不必记子技能名有价值 | 保留自然语言入口；允许 host 直接选中明确技能，避免先 router 再 action 的固定双跳 |
| 10 个技能 | capture/write/memory 有不同副作用；maintain 与 loop 是不同范围 | 暂保留 id 兼容。收敛共用规则；loop 只在长任务需要时用断点，不要求短检查建台账 |
| 子技能禁止衔接 | `multi-intent.md` 对 capture+organize、research+write 只允许“建议下一步” | 改为完成用户已授权的整条任务；额外提案仍需用户接受 |
| 建专题与记忆二次确认 | auto-suggest 的 L2 把明确请求与自动提案混为一谈 | 用户已明确请求即有授权；推测的稳定记忆仍只提案；写闸确认和发布授权保留 |
| 每次都读目录、契约、首页 | 已内联上下文时重复 I/O；简单查询不需扫描整库 | 复用本轮证据，按缺口读取；首页有则读，不强制创建 |
| 所有整理都必须落盘 | “总结这段”也可能被强制生成笔记 | 持久整理默认落盘；临时问答、仅对话或用户要求不保存时直接答复 |
| 必须调用未安装的改稿技能 | write 默认串 humanizer-zh / qu-aiwei-zh，包并未提供它们 | 改为可选增强；宿主缺能力时仍完成通用写作并说明限制 |
| 技能发现重复 | skills-runtime 同时生成 XML 全描述和 compact 描述 | 仅注入一份发现目录；全文在激活时加载 |
| 扩展技能资源归属 | loadSkillBody 漏传 extraRoots；loadSkillResource 优先 bundled，同名扩展可能读错 shared | 正文、资源和缓存使用同一选中来源；资源不能通过链接越出授权根 |
| 中英文预算不对称 | classifyTurn 的写动词只有中文 | 修复英文任务误判；未知复杂任务保留足够工具预算，减少关键词决定能力上限 |
| 查询完成闸 | assessGoalCompletion 对执行过工具的 [DONE] 一律索取文件路径 | 查询凭读取证据结束；写任务继续要求真实路径和未完成项检查 |
| 强制查询取证 | 防个人待办幻觉有价值；web_search 却被无参预调用 | 仅预取无参数的工作区列表；外部检索由模型带查询参数调用 |
| 目标协议 | 会话恢复、预算、取消与真实未完成状态有价值 | 保留底层状态；固定 PLAN 格式、研究轮次与路径正则是逐步替换目标，不能当作“验证完成”的充分条件 |
| 外部 evaluator | 可增加可信度，也增加延迟和一次模型判断 | 后续基于 trace 衡量收益；简单查询/局部编辑避免固定二次评审 |
| 插件权限 | permissions.ts 明示同 renderer 软门禁，并非隔离沙箱 | 保持诚实；先修生命周期与残留，不宣称获得强隔离 |
| 插件生命周期 | host 只跟踪 register，events.on/rpc.subscribe 未统一回收；激活失败不回滚 | 主机统一拥有订阅和槽位的释放；失败与热重载也清理 |
| Desktop 与 Obsidian | 共享 Kernel，但独立维护原生工具调用与文本 JSON 工具环 | 短期共享纯语义规则和回归用例；长期统一工具定义与错误契约，保留宿主适配层 |
| 规约治理 | AGENTS/CLAUDE/设计文档反复抄数量、命令、历史里程碑；发现过期 11 技能、35 命令 | AGENTS 只保留操作原则和阅读路由；详细纪律下沉，动态清单指向机器真源 |
| 测试结构 | 大量 regex 断言“存在某句话”，无法证明执行效果 | 保留必要文档契约；新增行为回归。模型行为需要真实 eval，静态文本不能替代 |
| Clip / 连接器 | URL 抓取与转换共用设计合理；网络身份、来源、降级不能靠提示词保证 | 保留明确来源及失败回执；后续加入真实页面 fixture 和离线转换回归 |

## 模型进步后的取舍

技能应提供模型不知道的产品知识、文件约定和真实工具边界。通用的“先理解、再计划、再检查”、穷举的触发同义词、每次固定链路、每种输出固定小标题、重复禁止猜测，已不值得层层叠加。把流程写成目标、必要输入和验收条件，让模型选择步骤。

仍必须由程序保证：路径与符号链接围栏、并发修改冲突、授权状态、凭据管理、原子写入、错误回执、取消与资源释放。更强模型不构成删除这些机制的证据。未针对本产品做模型基准前，不因型号更新直接扩大默认权限或取消边界。

依据：[OpenAI 关于新模型下精简 skills、AGENTS 与流程约束的指导](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)、[OpenAI Skills 文档](https://developers.openai.com/plugins/concepts/skills)、[Build skills 的渐进披露指导](https://learn.chatgpt.com/docs/build-skills)、[工作流评测与 trace](https://developers.openai.com/api/docs/guides/agent-evals)。这里的改造选择是结合代码的工程判断，并非官方对 topmind 的评价。

## 升级顺序与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| A：基础减负 | 规约按需读、简化 router、授权连续执行、可选依赖降级 | 入口体积下降；安装/打包引用完整；显式多意图不被规则拦截 |
| B：运行可靠性 | 查询与任务区分、扩展技能来源一致、插件释放和失败回滚 | 执行级回归；三仓类型/测试/构建；确认和写闸保持原有边界 |
| C：交互与上下文 | Obsidian 仅按需要加载近期动态/待办/反思，用户画像按相关性；Desktop 同样控制注入预算 | 真正统计输入 token、首次响应、完成率；在空白和真实 Vault 验证，不凭文档宣称完成 |
| D：可观察与评测 | 同一组中文/英文、查询/写入、跨技能、取消/续跑用例跑两端 | 正确路径、内容、无多余确认、无越权、失败诚实；记录模型版本和成本 |
| E：模块治理 | 按领域逐步拆 system-service、工具 schema、Obsidian sidebar；统一纯工具元数据 | 拆分不增加路由层；迁移旧实现后删除；不一次重构所有组件 |
| F：插件与发行 | 插件兼容声明、资源生命周期；独立干净构建、实际安装包启动、三平台检查 | mock 不能替代真机验收；有实测后再发布，不因本地测试通过就自动发版 |

本次落地与验证记录见文末；未实现项保留为待办，不标为全面升级完成。

## 本次实施记录

已完成 A、B，以及 C 的 Obsidian 按意图预取改造；D 增补了场景与确定性回归，尚未执行真实模型评测。E、F 的剩余工作见下表。

| 实测减负 | 改动前 → 改动后 | 降幅 |
|---|---|---|
| AGENTS 默认入口 | 24,010 → 4,264 字节 | 82.2% |
| CLAUDE 兼容入口 | 2,693 → 345 字节 | 87.2% |
| Router 技能文件 | 11,025 → 4,194 字节 | 62.0% |
| Capture 技能文件 | 7,049 → 3,149 字节 | 55.3% |
| Write 技能文件 | 4,833 → 3,099 字节 | 35.9% |

这是文件字节数的变化，不是 token、响应速度或成功率的等比例提升。详细开发纪律移动到按需阅读的 `docs/DEVELOPMENT.md`，没有删掉颜色、快捷键、启动和写闸质量要求。

实现包括：10 个技能描述精简；用户授权的连续工作；临时问答不强制保存；写作专用依赖可选；短巡检不强制持久台账；发现目录只注入一次；扩展技能正文/资源来源一致、激活读最新磁盘、路径检查覆盖符号链接；英文/短指令保留任务能力；查询不强制制造写入回执；查询预取不再无参调用 web_search；插件订阅统一回收、失败回滚、并发激活合并与激活中停用清理；Obsidian 按意图预取及续跑后完成状态修复；真实界面复核后合并 Desktop 空聊天区与输入区重复的 AI 配置引导，清理双语闲置文案。

已验证：

- 主仓 `npm run validate` 全部通过：Kernel/跨表面 683 项、UTR 151 项、Desktop 1,427 + 37 项测试；依赖、类型、语法、未声明标识符、死代码、i18n、构建与 pack:verify 通过。
- Skills `npm test` 60 项通过；tar.gz / zip / manifest / SHA256SUMS 构建成功。全部 10 个技能通过 CI 固定的 `skills-ref==0.1.1` 的 `agentskills validate`。内置旧 quick_validate 不接受标准 compatibility 字段，因此使用仓库官方校验器；未为迁就旧工具删除合法字段。
- Obsidian 类型检查、零警告 lint、183 项测试、vendored 独立构建和 pack:verify 通过。
- 真实 Electron 以 `/private/tmp` 隔离状态与工作区启动：通过真实新建工作区 IPC 初始化后，完整主界面可交互、10 个技能发现成功；AI 未配置状态只显示一个配置按钮，未捕获 renderer error；测试进程已关闭，未使用正式工作区或生产凭据。
- 新增 6 个路由/授权场景（评测数据现共 51 个），覆盖连续交付、明确记忆、建专题、仅聊天、英文指令和只读待办。场景文件并不等于真实 LLM 效果已测试。

剩余升级按价值顺序：

1. 用真实模型跑 51 个场景，两端记录输入量、首次响应、完成率、额外确认数与失败 trace，确定哪些 goal/evaluator 提示仍有收益。
2. 在真实 Obsidian 空白 Vault 验证安装、打开、聊天、取消/恢复；在 macOS/Windows/Linux 实际安装包中验收。当前 pack:verify 明示没有发行安装包，源码校验不代替该项。
3. 提取两端共用的纯工具定义/错误结构，减少工具指南和 schema 的重复维护；保留 Obsidian 与 Electron 的宿主网络、交互和权限适配。
4. 按改动热点逐步拆大模块；不机械按行数拆，也不新增通用流程框架。继续把非必要文案断言替换为行为或真源引用校验。
5. 为 Clip、WeRead、X 增补真实响应 fixture、离线回归和凭据缺失/网络失败用例。未做 live API、外部发布与远程部署。

上述剩余项没有包装成已完成。当前改动保留在三个仓库工作树，未提交、推送或发布。
