# Topmind 套件评估与实施计划

评估基线为 Desktop `4.19.2`、Obsidian `4.23.2`、核心 Skills `4.15.10`、Writing Skills `0.9.3`。实现取本地各仓，视觉基线取官网在线首页。10 月的审查和创作方案保留历史语境，本文记录本轮判断、差距和验收次序。设计数值及已交付行为随各端规范更新。 [TopMindSpace 官网](https://topmindspace.github.io/)

## 产品判断

核心价值是让用户把材料留下，从原来的内容继续做事，得到可复查、可再编辑的交付，再从实际文件找回。共享 Markdown 工作区使这条路径可以跨 Desktop、Obsidian 和已有 Agent 使用。最容易体现价值的时刻是「昨晚记的材料，今天能找到出处并接着做」，以及「修改一篇稿，能确认 AI 实际处理的是哪篇、改了哪里、如何恢复」。安装量、功能数和静态门禁通过率无法回答这些任务的完成质量。

| 表面 | 实际价值 | 判断与取舍 |
| --- | --- | --- |
| 核心 Skills | 用户沿用自己已经在用的 Agent，完成捕获、整理、交付与找回；有无 UTR 都有工作路径 | 一个日常入口加明确子技能直达合理。任务目标、对象、来源和权限比命令清单更有帮助。发布、连接器、修复、账本保持按需发现。 |
| Writing Skills | 从真实材料到可复制稿件、发布包或视觉方案。改稿和排版的分工保护作者语气与原文 | 八项能力覆盖清楚，标题、字体、排版、预览等可确定事项交给工具。研究、角度、叙述与语气交给模型。示例是可选参考；质量依据是事实、保真与交付可用性。 |
| Desktop | 独立承载长期工作，动态、专题、编辑器、交付与副驾可在一个工作区连续操作 | 保持中栏内容优先，AI 随对象出现。外观、视图、状态与连接器在多层可发现，首屏需进一步压低竞争入口。 |
| Obsidian | 在既有 Vault 内增加低摩擦动态和按需 AI，复用原生笔记、搜索、主题及快捷键 | 动态和写作有实际价值。窄侧栏优先呈现当前目标与下一步。保留宿主交互语言，默认继承主题。 |

最需要验证的用户价值是首次成功保存、次日成功找回、同一篇稿连续两轮只改指定范围、模型或工具不可用时仍能交付。暂时没有用户留存、任务成功率、真实模型质量或跨平台耗时数据。先以代表任务测量，之后再决定扩张哪些能力。

## 架构与工作流

1. **共享内容契约成立。** `topmind.yaml`、真实文件和 Kernel 写回构成稳定边界。规则、路径围栏、目标版本、恢复及写入回执属于程序层。UI、插件和 UTR 继续消费同一契约，工作区内容、会话和可重建状态各有来源。迁移必须验证旧工作区和自定义类别。
2. **技能和宿主分工正确。** `topmind-skills/topmind/SKILL.md` 以意图分流。`topmind-writing-skills/runtime/host-guide.md` 定义只在宿主有相应能力时执行。保留简短技能正文、单层参考、按需读取和真实能力降级。平台排版可以独立运行，研究、选角度、作者声音和段落调整应按当前材料决定。主题知识卡要给适用条件、例外和来源。 [Agent Skills 规范](https://agentskills.io/specification)
3. **共享语义优先于统一运行时。** Desktop 使用 Pi Agent Core，Obsidian 生产路径走兼容 JSON 工具循环。共同基线是任务对象、工具 schema、预算、授权、写回、可恢复状态和完成证据。先用同一组场景评估两端，再凭原生工具消息、流式取消、兼容性、上下文和延迟收益决定 Obsidian 是否迁移。 [Desktop 架构](../topmind-desktop/ARCHITECTURE.md) · [Obsidian 架构](https://github.com/topmindspace/topmind-obsidian/blob/main/ARCHITECTURE.md)
4. **单篇任务已具备良好边界。** 写作任务可冻结目标和参考，区分审阅和修改，给读窗口及编辑工具，排版独立运行。一般回合仍有完成证据的语义风险。`electron/ai-pi-runtime.mjs` 的通用目标协议会从回复文本和工具文本提取路径，`electron/lib/agent-goal-protocol.mjs` 的 `claimHasPathEvidence` 判断是否出现路径。路径可能只是引文或读取结果。应先写集成场景确认用户会看到的完成状态，再让普通任务的「改了什么」「已完成」分别依赖本轮结构化成功写入回执和任务类型，保留引用路径的独立展示。
5. **明确记忆与推测建议使用不同入口。** 核心 Skills 接受明确的画像更新请求。Obsidian 聊天已支持明确「记住」和指定完整旧原文的替换。宿主从本轮指令绑定字面内容，经 Kernel 画像写闸保存。推测继续用可审阅的建议卡。 [Obsidian 交互规范](https://github.com/topmindspace/topmind-obsidian/blob/main/DESIGN.md)
6. **技能分发已有快照机制，实际落后了一次。** 两端原本固定 `0.9.2`，写作包源码与变更记录已到 `0.9.3`。比较相差 39 个资源，运行时模块字节一致。本轮经显式脚本同步为同一摘要。后续发布前比较版本、摘要及宿主可用能力，由现有 `check:writing` 和插件发行门禁报告；独立包更新时可排队适配，不让常规构建读取邻仓最新内容。

### 给 AI 的空间与判断依据

| 任务类型 | 入口与完成依据 | 失败时用户看到什么 |
| --- | --- | --- |
| 对话、解释、找回 | 寒暄直接答。工作区问题少量检索并引用实际来源；只读任务允许完成且不产生写入回执。 | 没找到、来源冲突、目标不明分开说明。 |
| 编辑当前稿 | 发送前冻结稿件、选区和模式；修改对照实际版本。审阅返回建议，用户明确修改后才走限定写入。 | 草稿未保存或版本变化时提供保存、刷新、重试。暂停后保留真实已做修改。 |
| 多步创作、研究与整理 | 模型按依赖选择读取和步骤；仅在复杂任务展示计划。用来源、实际文件和最终产物判定完成。 | 展示已做和待做，恢复带回对象、已完成操作和共享预算，避免重复写或重复调用。 |
| 主动建议 | 依据、目标、动作和预览可见，确认后经 Kernel 执行。 | 忽略和取消可逆。已变化或失败的卡保留可操作状态。 |
| 渲染、图片与发布 | 模型决定表达方案，确定性工具渲染。区分读图、图片生成、PNG 渲染、平台发布。 | 按真实能力交付 HTML、文本或提示词，明确格式。外部发布的确认及平台回执单独处理。 |

用户路径按下列顺序检查，每条都覆盖空态、错误、加载、成功、回到原对象以及只用键盘：

- **首次使用、动态与收件。** 首次只问工作区所在处和必要模板；无模型也能记下。动态输入成功后保留当前周期和可打开的回执。Desktop 实机发现首次记录时把周期本标题算成第二条，本轮修正并保留用户写在分节前的正文。后续去重动态工具栏、侧栏和空态中语义重叠的动作，确保「记下」与「记一下」各自的存储去向可理解。
- **继续做和找回。** 专题和笔记以对象名称为中心，导航保留选中和编辑位置。全文搜索返回片段、路径和打开位置。Desktop 三栏优先保住正文宽度，窄窗一次展开主要辅助区。Obsidian 保留宿主文件树与编辑器，侧栏标签长文案和小宽度用实测决定折叠方式。
- **AI、建议与清单。** 输入旁显示当前文章或选区，运行后锁定指向和动作状态。取消、继续与重新生成按原对象可理解，错误附近可重试。检查副驾首屏顶栏多按钮、空态引导、长路径换行、生成中滚动、建议卡依据和真实结果。图标动作至少可键盘到达且焦点可见。
- **写作与交付。** 稿件 → 选目的 → 明确开始，排版预览与复制独立于模型。Obsidian 实测宽窗口弹窗约 660px，500px 视口弹窗约 400px，窄窗需要滚动才到达开始按钮。此次修复标题与说明点击范围不一致。下一步试验固定操作区和更紧凑的稿件栏，覆盖滚动边缘、中文输入法、Tab 顺序和读屏，确保焦点不被页脚挡住。
- **设置与可访问性。** 普通用户先看到模型能否连通、自动建议和恢复。进阶项放工具、上下文与管理。覆盖中英两语、系统与自定义主题、浅深和高对比、减少动效、200% 缩放、长文件名和异常状态。普通文字达到 4.5:1，关键图标与焦点指示达到 3:1，并实测键盘焦点不被遮挡。 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## Agent 完成证据整改

用离线模拟模型重放两端实际工具链。明确要求保存时，成功读取原文加模型声称完成仍记为未完成。已尝试的写入失败时，工具结果中的目标路径不进入变更列表。删除进入建议队列后结束本轮，原文件保留，已经完成的其他写入仍显示。Desktop 的本轮显式确认模式传到删除写闸。只读查询在最后一个可用回合给出答案时正常完成。

任务识别保留自然语言路径。对明确储存命令和已经尝试的写操作要求成功回执，普通研究与草稿可以在对话中交付。历史会话里的路径作为引用展示。当前回执证明哪些文件实际改变，是否做完复合要求仍需对照各项验收。

本批主仓 `npm run validate` 通过，含 Kernel 796、UTR 162、Desktop 1,572 项测试及 31 项打包检查。Obsidian 274 项测试、类型检查、lint、构建和打包校验通过。独立 Vault 用模拟模型验证引用展示、会话恢复和待确认删除，页面异常为零。实机 Obsidian 仍为 `1.12.7`，受支持版本和真实模型待验。

## 部分写入、确认后续跑与直接记忆

- 双端按写入操作记录成功和未解决的失败。模型声称全部完成时，已尝试的另一项写入若失败，结果仍为未完成，并显示本轮成功写入的文件。模型省略尚未尝试的工作仍由任务验收和后续模型评测发现。
- 待确认写入的接受与拒绝记录在现有队列文件，保留最近 80 项。续跑按会话保存的确认 ID 核对结果。确认后的删除回放以目标为准，保护后来在同一路径新建的文件。普通写入按同一工具和参数去重，已完成路径只作为前一轮的证据。缺少历史确认记录时请用户明确剩余任务。
- Obsidian 的「记住：……」和「更新我的情况：把「旧原文」改成「新原文」」由宿主直接处理。完整旧原文须唯一匹配活跃记忆。保存走 Kernel，未保存的编辑会阻止写入。未明确要求保存的内容沿用建议卡。

主仓 `npm run validate` 通过，含 Kernel 797 项、UTR 162 项、Desktop 1,578 项测试及 31 项打包检查。写回策略回归使用实际删除与确认队列验证 YAML 和调用覆盖。

Obsidian 276 项测试、类型检查、lint、构建和打包校验通过。隔离 Vault 的聊天框已验证直接记忆写入 `memory/profile.md`。记忆消息不绑定当前笔记，回执显示实际修改文件，模型请求数保持不变，页面异常为零。实机宿主为 `1.12.7`，受支持版本 `1.13.0` 及以上仍需复验。

## 真实模型评测首轮

使用 24 个合成场景，核心与写作各 12 个。真实模型以同一任务比较无技能、公开发行版和候选路由。发行版用公开 npm 的核心 `4.15.10`、写作 `0.9.3`，校验 SHA-512 后加载。18 份 `SKILL.md` 与本地对应文件逐字节一致。模型只收到合成任务、评测协议和所选公开技能。候选指引仅用于评测。

评测先检查目录路由，再检查模型交付文本和文件操作意图。产物分数覆盖明确范围、原文保真、归因、路径、HTML 顺序和工具受限时的回答。CLI 调用关闭工具，文件操作不执行。Desktop 和 Obsidian 的真实写回、线上模型与宿主交互、视觉产物及平台粘贴需单独验收。运行与复算见 [模型评测说明](../evals/README.md)。

每个场景在每组运行一次，合计 144 条结果。Claude CLI 请求的 `sonnet` 别名实际返回 `deepseek-v4-pro`。计时是每组各批次调用的累计时长。产物和路由分开计数，路由为预期主技能命中。对保留原文、代码块行数、日期及封面方案的评分规则统一复算，同组使用原始回包。样本中额外操作意图和虚报已发布均为零。

- **路由边界明确后更一致。** 两个模型都曾用 `topmind-organize` 处理「只找回已定结论」，候选指引都选回 `topmind`。四个答复均给出正确决议和出处。边界优先放在目录描述，待独立同义场景和宿主复验。
- **简单任务的基线已经很高。** 公开技能的总产物通过数为 47/48，无技能为 46/48，候选为 45/48。DeepSeek 在公开版中补齐了分类建议的源文件名，仍在未完成清单里附带了已完成项。候选组的两个保真稿保留了原文，但把解释混入可复制文本，需要手动删掉说明。样本支持保留候选做对照，当前不采用通用前置模型路由。
- **降级回答仍有改进空间。** 两个发布场景都正确停住，部分回复却暗示确认账号后便能代发，即使宿主缺少发布通道。下一轮将手动发布交付、权限确认和连接器可用性分别评分。
- **下一轮用真实宿主重放高价值场景。** 优先验证长文保真、缺图导出、确认后续跑和只读查找。固定文件、权限和测试模型，保存写入回执与文件差异。用独立措辞多轮复测后，再比较任务完成率、人工修订量和单任务延迟。

## 长文、交付与确认的宿主复验

实机用合成工作区和本机模拟模型重放。用带行号的工具结果证明尾句已经进入模型上下文，再逐字节比较落盘文件。短 `around` 窗口原先可能只返回关键词之前的行。Kernel 现在在匹配行会被漏掉时移动窗口，仍遵循行数上限，并保留本来已覆盖匹配的长窗口。

缺图时，实际导出的 HTML 与预览一致，图片清单标出缺失资源，源稿保持原样。人为制造图片清单路径冲突后，Desktop 复现了正文已保存但界面只显示底层错误的问题。两端现在单独报告已保存的正文和未保存的清单，完整导出时显示两个路径。Obsidian 的文件刷新也使用实际保存的路径。

Desktop `4.19.2` 在 Electron `44.4.4` 验证长文、缺图与部分导出、只读查找、待确认续跑。待确认时继续不调用模型，确认删除后重建同路径笔记，模拟模型重发删除时保留了新笔记，并生成了唯一的后续文件。脚本经真实 Electron IPC 启动 Agent，使用写作界面生成预览和导出。

Obsidian `1.15.0` 临时实例验证了同一批路径。只读查询先拦截错误写入，再读取真实待办并返回来源。查询结果由读证据和回答判定，不再因为模型发过写请求而显示缺少写入回执。测试比较待办文件前后的字节，并检查意外文件从未创建。

两端将排版检查和图片清单移到交付按钮之前，缺图文件可直接看到。补齐图片后尝试沿用旧预览，复制与导出被停用，已保存 HTML 保持原样。重新生成后，验证 HTML 内有实际图片数据，缺图提示消失。脚本入口见 [宿主实机复验](../evals/README.md#宿主实机复验)。

2026-11-17 最终复验通过。Obsidian 将导出回执滚入可视范围，并校验短窗下整条回执可见。Desktop 和 Obsidian 分别接收 10 次和 13 次本机模拟模型调用，两端均无页面异常。主仓完整门禁通过，含 Kernel 803 项、UTR 162 项、Desktop 1,579 项测试及 31 项打包检查。Obsidian 277 项测试、类型检查、lint、构建和打包检查通过。实际模型在宿主内的表现以及公众号和 X 实际粘贴仍待验收。
